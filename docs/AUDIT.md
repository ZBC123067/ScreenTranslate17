# ScreenTranslate17 v0.4.0 静态审计记录

## 本轮完成的修复

| 范围 | 修复内容 |
| --- | --- |
| 旧回调与页面切换 | 所有前台翻译操作均捕获独立页面标记与操作代际。页面切换、旋转、后台或设置变更后，OCR 和网络的旧回调只会清理自身忙碌状态，不会显示旧译文。 |
| 联网隐私 | 管理器在开始前检查敏感页面；翻译服务在工作队列真正发出 HTTP 请求前再次回到主线程执行同一资格检查。已切换或敏感页面不会发送旧文字。 |
| 占位符与缓存 | 敏感值使用随机且冲突检测过的 `[[ST_PRIVATE_...]]` 占位符；包含敏感数据的文本不缓存，即使用户关闭遮盖也一样。缓存键还隔离“遮盖开启/关闭”状态。 |
| 多进程可靠性 | 偏好和缓存写入使用 `flock` 锁与原子写入。缓存清除通过 Darwin 通知传播到每个注入进程，避免设置页只清空自身内存缓存。 |
| 自动模式 | 连续字幕与聊天在低电量或严重/临界温度时暂停；Timer 注册到 Common Modes。聊天启动时只建基线，之后只翻译新消息；失败条目在 5 秒后重试，成功后才记录为已处理。 |
| OCR | Vision 语言列表会与设备实际支持的识别语言取交集，避免某个 iOS 版本不支持指定语言时使整次 OCR 失败；后台 OCR 使用 autorelease pool。 |
| 输入翻译 | 回填前确认仍是同一个普通输入框，且原文未变；不会意外替换用户切换后的新输入框。 |
| 设置 | 所有可编辑配置去除首尾空格/换行并限长；非法 provider、显示模式和 DeepL 语言会在本地拒绝。新增绕过缓存、不写缓存的服务测试按钮。API Key 仍只能以 RootHide 偏好文件保存，建议使用可撤销、限额的独立 Key 或自建 HTTPS 代理。 |
| 打包与 CI | 移除了 `layout` 与 `internal-stage` 对同一 PreferenceLoader 文件的重复打包。macOS CI 解析 DEB，验证最终 tweak、设置 Bundle 二进制、Info.plist、PreferenceLoader 条目及 arm64e 架构。 |

## 已在当前环境验证

- 全部文本源码和配置可按 UTF-8 读取，无 U+FFFD 替换字符。
- 所有 XML plist、版本号、RootHide 配置、架构元数据、设置入口和新的静态规则均通过 `scripts/static_audit.py`。
- 静态检查额外验证 Objective-C / Logos 文本的注释与字符串边界、引用文件、去重打包和 workflow 的最终包验证步骤。
- 最终 ZIP 解压后会再次运行相同检查，并生成 SHA-256 校验文件。

## 仍需在 GitHub / iPhone 验证

- 当前 Windows 环境没有 RootHide Theos 与 Apple iOS SDK，无法完成 arm64e Objective-C/Logos 真编译。
- GitHub Actions 成功后，仍应先只在一个非敏感 App（建议 Safari）启用 Bootstrap 注入，检查启动、横竖屏、后台恢复、OCR、键盘和卸载是否正常，再逐个启用其他 App。
- 不要在银行、钱包、支付、密码、验证码或身份验证 App 启用注入；截图与 OCR 仅在内存中处理，但任意未被规则命中的联网翻译文本仍会发送给所选服务。
